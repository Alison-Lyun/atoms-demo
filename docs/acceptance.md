## 浏览器 E2E 复跑

从仓库根目录运行：

```bash
npx playwright install chrome
npm run test:e2e
```

配置会启动启用开发样例的本地服务。若复用已运行服务，需确保它启用了 `ENABLE_DEV_FIXTURES=true`。测试只使用明确标识的 fixture，不消耗模型额度。

目前的三个浏览器用例检查：

- 开发样例经过真实预览回报发布，新增数据在刷新后保留，并与另一个项目隔离。
- 候选预览的暂存写入在验证请求提交前不可见，提交后才进入项目数据。
- 候选启动抛出真实运行时异常后失败，已暂存的数据不落入当前项目。

失败时的截图和 trace 输出到 `../../work/playwright-results/`，以 `playwright.config.ts` 为准。完整通过后应记录执行命令、浏览器版本及结果，不应只根据界面截图将此项改为通过。

## Supabase 与部署验收

1. 执行迁移，启用匿名 Auth，以 `STORAGE_MODE=supabase` 启动应用。
2. 会话 A 创建项目并保存数据；会话 B 使用独立浏览器上下文。B 的列表不得出现 A 项目，直接访问 A 的项目 ID 应返回不可访问。
3. 使用普通 authenticated 身份验证直接写表受限；验证快照 RPC 不能写入其他 owner 的项目。
4. 同时提交基于同一 revision 的更新，确认旧写入收到冲突且无部分版本、消息或数据落库。
5. 重启服务或使用另一个应用实例，验证原会话项目仍由云端读取。
6. 部署后完成一次真实生成、数据写入、刷新及代码恢复；在新实例上取消进行中的任务，验证迟到结果不晋升。

填写部署地址前，还需验证目标环境的生成时长限制和模型连接。当前按项目计数的限流可被新建项目绕过；公开访问应结合额外限流、访问控制和费用上限。
